# Архитектурные решения

## Минимальный стартовый срез

Этап 0 добавляет реальные точки входа Go/Chi и React/Vite. Папки модулей появляются с первым кодом. Это сохраняет связь структуры с реализацией и делает каркас проверяемым без БД и прикладного API.

## Управление зависимостями

Go modules фиксируют Chi и контрольные суммы. pnpm из `frontend/package.json` и `frontend/pnpm-lock.yaml` фиксирует клиентское дерево. Выбран Go 1.27 и Node.js 26. Новые зависимости подключаются вместе с использующим их кодом или проверками.

## Проверки фронтенда

ESLint использует рекомендованные правила JavaScript и TypeScript, Prettier проверяет форматирование файлов фронтенда. Файл `pnpm-lock.yaml` проверяется отдельной установкой с `--frozen-lockfile`.

## PostgreSQL и миграции

API использует pgxpool и остаётся доступен для liveness при потере БД. Readiness ограничен отдельным таймаутом. Compose запускает API после Goose. Миграции встроены в отдельную команду, сериализуются advisory lock PostgreSQL и выполняются транзакционно.

Позиция уникальна в границах владельца и статуса. Отложенная проверка уникальности позволяет менять порядок несколькими SQL-командами в транзакции. Хеш refresh-токена хранится как 64 строчных шестнадцатеричных символа SHA-256. БД проверяет форму PHC для Argon2id, а параметры и подлинность будет проверять код авторизации.

## Authentication

- JWT подписывается HS256. Ключ генерируется вне приложения. Конфигурация проверяет канонический Base64 и размер, а также отбрасывает очевидно вырожденные значения. Случайность ключа обеспечивается генератором.
- Argon2id использует 64 МиБ, time cost 3 и parallelism 1. Соль 16 байт, результат 32 байта. Верификатор принимает этот профиль. Отсутствующий аккаунт и повреждённый хеш используют dummy-проверку. Достигнув лимита одновременных вычислений, сервер возвращает 429. Локальный benchmark на Intel Core i7-12700H, Linux/amd64, 8 итераций показал 268 мс и 67,1 МБ аллокаций на хеш. Измерение в целевом production-окружении относится к подготовке релиза.
- Login, refresh и смена пароля используют блокировку строки пользователя. Login сверяет хеш под блокировкой. Ошибка вставки откатывает отзыв старого refresh-токена. При повторном использовании отозванного токена новый запрос получает 401, а действующая сессия-потомок сохраняется.
- Rate limiter работает на процесс, ограничивает число ключей и очищает их при смене окна. IPv4 группируется по адресу, IPv6 по /64. Заголовки прокси игнорируются. При подключении Caddy нужно настроить доверенную цепочку, иначе лимит будет учитывать адрес прокси.
