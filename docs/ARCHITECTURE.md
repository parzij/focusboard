# Архитектура

Проект состоит из Go API и React SPA в одном репозитории. Утверждённые границы описаны в [§3 ТЗ](../SPECIFICATION.md#3-архитектура).

## Каркас этапа 0

- `backend/cmd/api` собирает Chi router и HTTP server, задаёт таймауты и обрабатывает SIGINT/SIGTERM. По умолчанию слушает `127.0.0.1:8080`, адрес можно задать через `HTTP_ADDR`.
- `frontend/src/main.tsx` монтирует React. `src/app` содержит корневой компонент, `src/shared/styles` — базовые стили.
- Компоненты запускаются независимо. Маршруты API, подключение к БД и проксирование появятся на следующих этапах.

## Целевая архитектура

Caddy отдаёт статику Vite с SPA fallback и сохраняет префикс `/api/v1` при проксировании в Go. Браузер обращается к API с того же origin. PostgreSQL доступна API и одноразовому заданию Goose.

Backend состоит из модулей auth, users, tasks и statistics. Middleware устанавливает проверенный user ID, Handler обрабатывает HTTP, Service реализует правила и транзакции, Repository выполняет параметризованный SQL. Statistics читает историю задач. Конструкторы принимают явные зависимости.

На фронтенде `pages` собирает экраны из `features` и `entities`; `shared` содержит общие UI-компоненты, стили и API client. TanStack Query управляет серверными данными. Access token живёт в памяти, восстановление сессии проходит через refresh cookie.
