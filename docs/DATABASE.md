# База данных

На этапе 0 зафиксирована модель из [§5 ТЗ](../SPECIFICATION.md#5-модель-данных-и-postgresql). PostgreSQL, pgxpool, SQL-миграции Goose и интеграционные проверки входят в этап 1.

| Таблица | Назначение и ограничения |
| --- | --- |
| `users` | UUID, имя, уникальный нормализованный email, Argon2id PHC-хеш, timestamps |
| `tasks` | Владелец, заголовок, описание, статус, позиция, nullable due date и soft delete |
| `refresh_tokens` | Владелец, уникальный SHA-256 хеш, абсолютный срок действия и время отзыва |
| `task_history` | Задача, предыдущий и новый статус, время события. Запись добавляется при создании и каждом реальном переходе |

Дедлайн — `DATE`, события — `TIMESTAMPTZ`. Позиции активных задач непрерывны внутри пары «владелец и статус». У удалённой задачи позиция равна NULL, история сохраняется. Изменение статуса и запись истории входят в одну транзакцию. Мутации доски сериализуются блокировкой строки владельца. Запросы к пользовательским объектам ограничиваются идентификатором владельца.

Каждая миграция получает Up/Down. Проверка включает Up, Down и повторный Up на чистой тестовой БД. Команды обслуживания, резервного копирования и восстановления будут проверены на рабочем Compose-окружении.
